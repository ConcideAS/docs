---
title: Konfiguracja dla programistów
---

Saga jest dostępna jako serwer [MCP](https://modelcontextprotocol.io), dzięki czemu agenci i asystenci AI — Claude, ChatGPT, Cursor oraz niestandardowi agenci — mogą używać Twojej przestrzeni roboczej Saga jako narzędzia. Agent może zadawać Sadze pytania, przeszukiwać i odczytywać dokumenty projektu oraz uruchamiać Twoje przepływy pracy, korzystając z Twojego własnego dostępu.

To odwrotność podłączania zewnętrznych serwerów MCP do Saga. Tutaj Twoja przestrzeń robocza Saga *jest* serwerem, do którego łączą się inne narzędzia.

## Zanim zaczniesz

Potrzebujesz:

- **adresu URL platformy** oraz **klucza API**. Oba pochodzą z sekcji **Ustawienia > Zarządzanie kluczami API** w Saga. Otwórz tę stronę, utwórz klucz, jeśli go nie masz, i skopiuj obie wartości.
- Klienta MCP obsługującego transport streamable HTTP (Claude Desktop, Claude Code, Cursor lub dowolnego niestandardowego agenta zbudowanego na MCP SDK).

<Note>
Każdy klient ma własną domenę Saga, więc Twój punkt końcowy MCP to Twój własny adres URL platformy z dodanym `/api/mcp`. Użyj adresu URL platformy wyświetlanego w sekcji **Ustawienia > Zarządzanie kluczami API** — nie zgaduj domeny.
</Note>

## Podłączanie klienta

Większość klientów potrzebuje jedynie adresu URL punktu końcowego oraz nagłówka `Authorization`.

- **Punkt końcowy:** `https://<your-domain>.sagalegal.io/api/mcp`
- **Nagłówek:** `Authorization: Api-Key <your-api-key>`

W przypadku klienta, który odczytuje plik `.mcp.json` (na przykład Claude Code), dodaj:

```json
{
  "mcpServers": {
    "saga": {
      "type": "http",
      "url": "https://<your-domain>.sagalegal.io/api/mcp",
      "headers": { "Authorization": "Api-Key <your-api-key>" }
    }
  }
}
```

Zastąp `<your-domain>` swoim adresem URL platformy, a `<your-api-key>` kluczem z sekcji **Ustawienia > Zarządzanie kluczami API**.

<Note>
Niektórzy klienci pozwalają jedynie wkleić token bearer. W takim przypadku użyj `Authorization: Bearer <your-api-key>` zamiast tego — Saga akceptuje Twój klucz API w obu formach.
</Note>

## Co może robić agent

Po połączeniu agent ma dostęp do następujących narzędzi:

| Narzędzie | Co robi |
|------|--------------|
| `ask_saga` | Zadaje Sadze pytanie i zwraca odpowiedź, tak samo jak podczas czatu w aplikacji. |
| `list_projects` | Wyświetla Twoje projekty, w tym te udostępnione Tobie. |
| `list_project_documents` | Wyświetla dokumenty w projekcie. |
| `search_project_documents` | Przeszukuje bazę wiedzy projektu i zwraca najbardziej odpowiednie sekcje. |
| `fetch_project_document` | Zwraca pełny tekst dokumentu. |
| `list_workflows` | Wyświetla Twoje przepływy pracy oraz dane wejściowe oczekiwane przez każdy z nich. |
| `execute_workflow` | Uruchamia przepływ pracy z wejściami tekstowymi i zwraca wynik. |

Każde narzędzie działa w Twoim imieniu. Agent widzi tylko projekty, dokumenty i przepływy pracy, do których Twoje konto ma już dostęp — z tymi samymi uprawnieniami, które masz w aplikacji internetowej.

## Bezpieczeństwo

- Traktuj swój klucz API jak hasło. Każdy, kto ma klucz i Twój adres URL platformy, może działać jako Ty za pośrednictwem Saga.
- Rotuj lub odwołuj klucz w dowolnym momencie w sekcji **Ustawienia > Zarządzanie kluczami API**. Odwołanie natychmiast zatrzymuje każdego połączonego agenta.
- Jeśli klucz mógł wyciec, odwołaj go i utwórz nowy, a następnie zaktualizuj konfigurację klienta.

## Rozwiązywanie problemów

- **Klient nie może się połączyć lub zwraca błąd 401 Unauthorized** — sprawdź, czy punkt końcowy kończy się na `/api/mcp`, czy nagłówek to `Authorization: Api-Key <your-api-key>` oraz czy klucz nie wygasł i nie został odwołany. W razie potrzeby utwórz nowy klucz w sekcji **Ustawienia > Zarządzanie kluczami API**.
- **Przepływ pracy zgłaszany jest jako wstrzymany** — przepływy pracy, które w trakcie czekają na dane wejściowe, nie mogą być wznawiane przez MCP, a wejścia plikowe nie są obsługiwane. Uruchamiaj je zamiast tego z aplikacji Saga.
