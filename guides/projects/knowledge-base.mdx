---
title: Knowledge base
---

The knowledge base is the document library inside a project. Every file you upload is processed by Saga — the text is extracted, broken into passages, and indexed so the AI can find the right material on demand. When you ask a question in a project chat, the AI searches across the entire knowledge base and pulls the passages most relevant to your question into the answer, with citations linking back to each source. You don't choose which documents the AI looks at — it decides per question, based on what you're actually asking.

## Add documents

Drag and drop files or folders directly into the knowledge base panel, or click **Upload** to browse your computer. If your organization has SharePoint, Epona365, or [iManage](/guides/integrations/imanage) configured, you can import files from those services as well.

Saga supports a wide range of file types:

| Category      | Formats                                      |
| ------------- | -------------------------------------------- |
| Documents     | PDF, DOC, DOCX, TXT, MD, HTML, CSV, ODT, UDF |
| Spreadsheets  | XLS, XLSX, ODS                               |
| Presentations | PPTX                                         |
| Email         | EML, MSG                                     |
| Images        | PNG, JPG, JPEG, GIF, WEBP, TIFF              |

The maximum file size is 1 GB. A project can hold up to 1,000 documents. When a project is near its document limit, the knowledge base header shows a usage badge with the number of documents used and the limit, such as `820/1000`. The badge appears when the project reaches about 80% of its document limit. Below that threshold, it is not shown.

After upload, each file goes through processing before it's available to the AI. You can keep working while this happens — documents become available automatically as they're ready. If a file fails to process, you can retry it from its action menu. If more than one upload fails, a recovery bar appears at the top of the knowledge base so you can **retry all** failed uploads or **delete all** failed uploads in one step.

While a document is processing, its checkbox and bulk actions are temporarily disabled — actions on already-processed documents remain available. If the document counter ever seems stuck at a higher number than your file list (for example you've deleted files but uploads are still blocked), refresh the page; the counter recalculates from the server on reload. If it's still wrong after refresh, contact support.

After an upload, Saga scrolls to the first new file and opens its folder if needed. New files show a **New** label for a few seconds.

## Folders and tags

You can organize documents with folders and color-coded tags.

**Folders** let you replicate your existing file structure. Create nested folders, drag documents between them, and download an entire folder as a ZIP when you need to share files outside Saga. Your folder expand/collapse state is saved automatically and persists across page refreshes, so you always return to the view you left off at.

When you drag files from your computer onto a folder, they upload into that folder. A drop on the list outside a folder uploads at the root. You can also drag document rows onto a folder to move them, with an **Undo** option. Rest a drag on a folder to expand it, so you can reach a subfolder. Read-only members cannot drag files or rows.

**Tags** work across folders. Assign a tag to a document, give it a color, and use the tag filter to show only documents with that label. Tags are useful for marking document types, review status, or anything else that cuts across your folder structure.

In a project chat, you can ask Saga to sort documents into folders or tags. Saga proposes the changes. You can review and edit the proposal: change the folder or tags for each document, and choose which documents to apply. Nothing moves until you confirm. This is not available in the Word or Outlook add-in.

## Document actions

Each document has an action menu where you can rename it, move it to a different folder, manage its tags, download it, retry processing, or delete it.

To act on several documents at once, use the checkboxes next to each document or folder. With a selection active, you can **download**, **delete**, **move**, or **tag** all selected documents in one step. Folder checkboxes show a partial-selection indicator when only some files inside are selected, so you can see exactly what's included.

To copy documents into another project, choose **Copy to Project** in a document's action menu, or select several documents and use **Copy to Project** in the selection bar. Pick a project where you have edit access. The copies go to the top level of that project's knowledge base. Saga skips documents that are already in that project, are still processing, or would go over its document limit, and tells you which ones. Choose **Open Project** to go there.

Use **Filter > Sort by** to sort files by **Name** or **Date uploaded**. Folders stay in A to Z order. Your choice lasts for the session.

## Duplicate filenames

You can upload several documents with the same filename to a knowledge base — Saga assigns each its own internal identifier. When the knowledge base detects identical files, it automatically applies a **Duplicate** tag so you can spot them via the tag filter.

That said, when the AI fetches documents by name (either from a chat's attachments or from a project knowledge base), identical names are ambiguous: the AI surfaces a follow-up listing each match and asks which one you meant. To avoid that round-trip, give files distinctive names — even adding `(v2)` or a date is enough.
