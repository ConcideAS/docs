title: Entwickler-Setup
---

Saga ist als [MCP](https://modelcontextprotocol.io)-Server verfügbar, sodass KI-Agenten und -Assistenten — Claude, ChatGPT, Cursor und benutzerdefinierte Agenten — Ihren Saga-Arbeitsbereich als Werkzeug nutzen können. Der Agent kann Saga Fragen stellen, Projektdokumente durchsuchen und lesen sowie Ihre Workflows ausführen, alles mit Ihrem eigenen Zugriff.

Dies ist die Umkehrung des Verbindens externer MCP-Server mit Saga. Hier *ist* Ihr Saga-Arbeitsbereich der Server, mit dem sich andere Werkzeuge verbinden.

## Bevor Sie beginnen

Sie benötigen:

- Ihre **Plattform-URL** und einen **API-Schlüssel**. Beide finden Sie in Saga unter **Einstellungen > API-Schlüsselverwaltung**. Öffnen Sie die Seite, erstellen Sie einen Schlüssel, falls Sie noch keinen haben, und kopieren Sie beide Werte.
- Einen MCP-Client, der den streambaren HTTP-Transport unterstützt (Claude Desktop, Claude Code, Cursor oder einen beliebigen benutzerdefinierten Agenten, der auf dem MCP-SDK basiert).

<Note>
Jeder Kunde hat seine eigene Saga-Domain, daher ist Ihr MCP-Endpunkt Ihre eigene Plattform-URL mit dem Zusatz `/api/mcp`. Verwenden Sie die unter **Einstellungen > API-Schlüsselverwaltung** angezeigte Plattform-URL — raten Sie die Domain nicht.
</Note>

## Einen Client verbinden

Die meisten Clients benötigen nur die Endpunkt-URL und einen `Authorization`-Header.

- **Endpunkt:** `https://<your-domain>.sagalegal.io/api/mcp`
- **Header:** `Authorization: Api-Key <your-api-key>`

Für einen Client, der eine `.mcp.json`-Datei liest (zum Beispiel Claude Code), fügen Sie hinzu:

```json
{
  "mcpServers": {
    "saga": {
      "type": "http",
      "url": "https://<your-domain>.sagalegal.io/api/mcp",
      "headers": { "Authorization": "Api-Key <your-api-key>" }
    }
  }
}
```

Ersetzen Sie `<your-domain>` durch Ihre Plattform-URL und `<your-api-key>` durch den Schlüssel aus **Einstellungen > API-Schlüsselverwaltung**.

<Note>
Bei manchen Clients können Sie nur ein Bearer-Token einfügen. Verwenden Sie in diesem Fall stattdessen `Authorization: Bearer <your-api-key>` — Saga akzeptiert Ihren API-Schlüssel in beiden Formen.
</Note>

## Was der Agent tun kann

Nach der Verbindung verfügt der Agent über diese Werkzeuge:

| Werkzeug | Was es tut |
|------|--------------|
| `ask_saga` | Stellt Saga eine Frage und gibt die Antwort zurück, genau wie beim Chatten in der App. |
| `ask_saga_project` | Stellt eine Frage, die auf den Dokumenten eines Projekts basiert, und gibt eine zitierte Antwort zurück. Der Chat wird im Projekt gespeichert. |
| `list_projects` | Listet Ihre Projekte auf, einschließlich der mit Ihnen geteilten. |
| `list_project_documents` | Listet die Dokumente in einem Projekt auf. |
| `search_project_documents` | Durchsucht die Wissensdatenbank eines Projekts und gibt die relevantesten Abschnitte zurück. |
| `fetch_project_document` | Gibt den vollständigen Text eines Dokuments zurück. |
| `list_assistants` | Listet die aktiven benutzerdefinierten Assistenten in Ihrem Arbeitsbereich auf. |
| `ask_saga_assistant` | Stellt einem benutzerdefinierten Assistenten eine Frage und wendet dessen Anweisungen an. |
| `list_prompts` | Listet Einträge der Prompt-Bibliothek auf, persönlich, Organisation, Saga Lab oder alle, mit optionaler Suche. |
| `fetch_prompt` | Gibt den Text eines Prompts und seine Platzhalterfelder zurück. |
| `list_workflows` | Listet Ihre Workflows und die Eingaben auf, die jeder einzelne erwartet. |
| `execute_workflow` | Führt einen Workflow mit Texteingaben aus und gibt das Ergebnis zurück. |
| `get_workflow_status` | Gibt den Status eines Workflow-Laufs und den Status jedes Schritts zurück. |
| `fetch_workflow_step_result` | Gibt die Ausgabe eines abgeschlossenen Schritts zurück. |
| `submit_workflow_input` | Beantwortet den Schritt, bei dem ein Lauf wartet, und setzt den Lauf fort. |
| `resume_workflow` | Startet einen Lauf, der erstellt, aber nie gestartet wurde. |
| `list_project_folders` | Listet die Ordner und Tags der Wissensdatenbank eines Projekts auf, das Sie öffnen können. |
| `list_project_memories` | Listet die kurzen Fakten auf, die im Projektgedächtnis eines Projekts gespeichert sind, das Sie öffnen können. |
| `list_chats` | Listet die persönlichen Chats und Projekt-Chats auf, die Sie in der App öffnen können. Chats außerhalb der Aufbewahrungsfrist werden ausgelassen. |
| `fetch_chat` | Gibt die Nachrichten eines persönlichen Chats oder Projekt-Chats zurück, den Sie öffnen können. Lange Chats werden auf das Token-Budget gekürzt. |
| `list_grid_reviews` | Listet Ihre Rasterprüfungen auf. Übergeben Sie `project_id`, um nur die Prüfungen eines Projekts aufzulisten. |
| `fetch_grid_review_answers` | Gibt die Antworten einer Rasterprüfung zurück, die Sie öffnen können. Große Prüfungen werden auf das Token-Budget gekürzt. |
| `search_legal_research` | Durchsucht eine juristische Datenbank, auf die Sie Zugriff haben. Eine Rechtsordnung außerhalb Ihres Workspace wird abgelehnt. |
| `list_workflow_runs` | Listet die Workflow-Läufe auf, die Sie gestartet haben. Verwenden Sie `get_workflow_status`, um einen Lauf zu lesen. |
| `fetch_workflow` | Gibt die Schritte eines Workflows in Reihenfolge zurück. Für jeden Eingabeschritt zeigt es, was Sie angeben müssen und ob der Agent es über MCP angeben kann. |
| `describe_action` | Erklärt, wie Sie die Saga-MCP-Werkzeuge verwenden. Ohne Argumente listet es jedes Werkzeug und die übliche Aufrufreihenfolge auf. Mit einem Werkzeugnamen gibt es die Eingaben, einen Beispielaufruf, die Rückgabe des Werkzeugs und den nächsten Aufruf zurück. |

Jedes Werkzeug wird als Sie ausgeführt. Der Agent sieht nur die Projekte, Dokumente, Chats, Rasterprüfungen und Workflows, auf die Ihr Konto bereits zugreifen kann — dieselben Berechtigungen, die Sie in der Web-App haben.

## Sicherheit

- Behandeln Sie Ihren API-Schlüssel wie ein Passwort. Jeder mit dem Schlüssel und Ihrer Plattform-URL kann über Saga als Sie agieren.
- Rotieren oder widerrufen Sie den Schlüssel jederzeit unter **Einstellungen > API-Schlüsselverwaltung**. Ein Widerruf stoppt jeden verbundenen Agenten sofort.
- Falls ein Schlüssel möglicherweise durchgesickert ist, widerrufen Sie ihn und erstellen Sie einen neuen, und aktualisieren Sie anschließend Ihre Client-Konfiguration.

## Fehlerbehebung

- **Der Client kann sich nicht verbinden oder gibt 401 Unauthorized zurück** — prüfen Sie, ob der Endpunkt auf `/api/mcp` endet, ob der Header `Authorization: Api-Key <your-api-key>` lautet und ob der Schlüssel nicht abgelaufen oder widerrufen wurde. Erstellen Sie bei Bedarf einen neuen Schlüssel unter **Einstellungen > API-Schlüsselverwaltung**.
- **Ein Workflow wartet auf Eingabe**: Verwenden Sie `submit_workflow_input`, um eine Texteingabe zu beantworten und den Lauf fortzusetzen. Wenn der Schritt eine Datei benötigt, öffnen Sie den Lauf in Saga und laden Sie die Datei dort hoch.
